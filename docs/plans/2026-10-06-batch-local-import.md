# 本地 Markdown 批量与路径导入

## 目标与约束

在现有纯浏览器扩展中增加多文档队列，一次操作依次同步多个 Markdown/HTML；每份文件创建独立文章或飞书文档。用户明确选择本地文件/文件夹路径。继续复用单文档转换、权限申请与服务端保存验证。

浏览器不会把任意输入的磁盘路径变成读取权限。提供“授权目录”按钮，由用户选择目录；再把相对路径或用户填写的目录完整路径映射到该授权目录。完整路径只用于匹配，不是自动获取磁盘权限。保留原生多文件和文件夹选择作为兼容入口。

## 方案

推荐授权目录加路径队列：符合纯浏览器约束，支持多行文件/目录路径，目录递归匹配。仅使用原生多选无法按粘贴路径过滤；本机连接程序能直接读路径但与既定约束冲突。

## 文件与行为

- `lib/local-batch.ts`：路径解析、目录内匹配、串行队列执行与安全重试判定；不调用 Chrome API。
- `lib/local-directory.ts`：只读选择与有界扫描授权目录，生成与现有转换器兼容的文件引用。
- `local-import/LocalImportPage.tsx`：待上传文档列表、预览/标题、勾选、批量上传、完成当前项后停止、每份结果链接；单文档与 OneNote 保持可用。
- 仅将当前文档正文发给后台。目录读取限 5000 个条目、32 层、50 MiB 支持文件；一次队列最多 100 份文档。图片在每份准备时读取，避免同时保存整个批次的内嵌正文。
- 成功平台不重复上传；缺图和准备失败阻止该项，其他项继续；飞书已创建但失败的文档禁止直接重试；后台响应不确定的项需检查历史，不自动重试。
- 浏览器页面持有文件引用，关闭页面后不继续启动下一项，已发起的后台任务继续。只持久保存批次结果摘要，不持久保存文件访问授权或自动恢复上传。

## 实施与验证

依次实现路径与执行器、只读目录读取、页面队列、回归测试与生产构建。验证中文/Windows/UNC 路径、越界、重复、缺图、串行执行、部分成功、安全重试、停止，以及编译后 UI 与实际 Chrome 飞书两份短文档。更新原安装目录保留扩展 ID，打包 GPL 源码与报告。出现问题可重载 preview.4 安装包回滚。
