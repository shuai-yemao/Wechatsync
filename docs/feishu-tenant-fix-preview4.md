# 飞书文档租户识别修复（preview.4）

2026-10-06，通过 Chrome 官方 DevTools MCP 1.10.1 连接用户授权的实际 Chrome 154，定位并修复同步失败。扩展仍完全在浏览器中工作。

## 已确认的故障

原实现只检查域名是否属于 `feishu.cn` 等飞书域名，并排除少数登录域名。飞书招聘网站 `*.jobs.feishu.cn` 因而被当成云文档租户；共享登录 Cookie 又使认证检查返回 `isAuthenticated: true`。实际浏览器中的单平台认证检查复现了这个结果，历史同步也存在租户地址校验失败。

## 修复内容

- 排除招聘、官网和登录等保留站点，并要求标签页位于云文档路由（如 `/drive/`、`/docx/`、`/wiki/`）。活动招聘标签页不再覆盖实际云文档标签页。
- 飞书平台的登录入口改为 `https://feishu.cn/drive/home/`，进入后由飞书跳转到当前账号的文档租户。
- 飞书登录状态每次检查当前标签页，不再复用五分钟的认证缓存；其他平台继续使用既有缓存。
- 保留新文档必须属于当前租户、必须为空、粘贴后必须服务端回读的校验。

1. 新增招聘站点回归：仅招聘页时认证失败且不读 Cookie、不创建文档；招聘页活动时仍选中非活动云文档页；官网、登录、非文档路由排除。修复前相关用例失败，修复后通过。
2. 扩展测试 46/46 通过，TypeScript 检查与生产构建通过。
3. 用户实际 Chrome 中重载 `2.0.9-feishu-local-preview.4`，通过本地导入界面选择调试生成的 Markdown 与 PNG，只同步飞书。真实账号创建文档成功，插件保存回验成功。
4. 刷新新文档后，再次请求服务端 `client_vars`：HTTP 200、code 0、块树完整，正文、C 代码块、远端图片标识和有效链接属性均存在。链接属性中的 URL 需解码后比较。

测试文档标题为“飞书同步验证 20261006”，仅包含调试生成的内容。真实文档链接和脱敏后的 DevTools 记录保存在本机输出目录，不写入公共仓库。

## 使用方法与边界

先在浏览器打开并登录云文档主页，再在插件中选择“导入”，同时选择 Markdown 和配套图片，检查预览后同步飞书。保持导入页打开直至出现同步结果。

本次真实验证覆盖一个账号的一份短文档、一个 C 代码块、一张本地 PNG 和一个 HTTPS 链接。大型文档、多租户切换、其他图片格式及 OneNote OAuth 仍需分别验证。飞书网页接口属于私有协议，后续可能变化；不能用创建成功代替正文保存验证。
