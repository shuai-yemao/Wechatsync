# preview.2：公告配置和微博登录检查修复

用户启动插件时看到 `[RemoteConfig] Config fetch failed: 404` 和 `[Weibo] Failed to find config in HTML`。本次修复针对启动诊断与失败降级；真实飞书保存、OneNote 授权和微博账号发布仍需账户验收。

## 确认的原因

- 2026-10-05 直接请求上游公告配置地址，HTTP 状态为 404。此配置只提供公告横幅，不参与正文转换或飞书写入。
- 原实现只记录成功请求时间，失败后每次 worker 唤醒都可能重试；安装事件和启动检查也会重复发起请求。
- 微博适配器没有检查 HTTP 状态。HTML 缺少用户配置时直接记录 console.error 并返回未登录，无法区分访客页面、服务故障与配置格式变化。
- 原扩展构建的 tsc 向源码目录输出 JS；后续 Vitest/Vite 的无扩展名导入可能优先选择旧 JS。修复设置 noEmit，由 Vite 负责打包。当前本机的 372 个未跟踪同名编译文件已移至工作目录备份，未移动 Git 跟踪文件。

## 最终行为

公告请求合并并发任务，记录每次尝试时间，失败也遵循六小时检查间隔；请求最多十秒。404 使用已有缓存并保存 unavailable/404 状态；503、网络和 JSON 错误仍保存诊断并输出警告。不会清除平台登录、同步历史或用户设置。

微博 401 返回未登录；其他非成功 HTTP 返回带状态码的诊断。HTML 缺少或包含非法配置时，返回中文操作提示，不把例行认证检查记成 worker 程序错误。重新检查会更新会话状态，避免注销后继续使用旧用户缓存。界面保留认证诊断，平台行显示“检查登录”，悬停可查看原因；点击仍打开原平台登录页。所有平台的检查继续独立完成。

版本名为 `2.0.9-feishu-local-preview.2`，延续 preview.1 的 debugger 权限修复。

## 更新与回滚

构建文件更新至用户之前加载的同一 chrome-extension 目录，旧 ZIP 保留。打开 chrome://extensions，点击本插件重新加载按钮，然后清除错误页面中的历史记录并重新打开插件。详情中的版本名应为 preview.2。旧报错记录不会随源文件更新自动消失。

若需回滚，停止插件后将 preview.1 ZIP 解压覆盖到同一目录并重新加载。两版沿用相同目录，避免扩展 ID 和 OneNote 重定向地址改变。
